# Pressure Pack — Staging and Verification

This document defines the controlled installation path for `VS-C8-SCI-FP-PRESSURE-V1`.

The pack is **DRAFT educational content**. Installing it stages reviewable Learning Studio records; it does **not** publish content to students or the public catalogue.

## Safety rules

- Do not run a database migration for this pack.
- Do not run `database/run_all_migrations.sql`.
- Do not run any seed script.
- Do not use Docker for production deployment.
- Do not change a resource/question/assessment to `PUBLISHED` as part of installation.
- Use only an existing `SUPER_ADMIN` user for an explicit staging write.
- Run the installer dry-run before every first staging attempt in an environment.

## What the installer stages

The installer reads the canonical files in this directory and creates or reuses DRAFT Learning records for:

- one bilingual Class 8 Science Pressure article resource;
- all 12 bilingual Pressure questions;
- the low-stakes Pressure practice assessment;
- the Pressure mastery assessment;
- `CLASS_8` grade mappings;
- `COMMON` cross-board mappings;
- Science subject mapping when a Science subject row is available;
- bilingual English/Hindi question options and explanations.

The installer is deliberately idempotent by stable public slugs/codes. It refuses to overwrite matching content that has already moved beyond `DRAFT`.

The concept-video, practical-video and audio files are **not generated by this installer**. Their production scripts/specifications remain in `media-scripts.md` and must pass the media/accessibility review before any corresponding media resource is published.

## 1. Build first

From the repository root after the release code has been checked out:

```bash
npm --prefix shared/contracts ci
npm --prefix shared/contracts run build
npm --prefix backend ci
npm --prefix backend run build
```

The compiled installer will be:

```text
backend/dist/scripts/installPressurePack.js
```

## 2. Mandatory dry-run

From the repository root:

```bash
node backend/dist/scripts/installPressurePack.js
```

Expected final output includes:

```text
DRY RUN ONLY — no database writes were made.
```

The dry-run validates the manifest, bilingual lesson split, 12-question bank, question answers and quiz references without querying or changing the database.

## 3. Explicit DRAFT staging

Only after the dry-run passes and an authorised `SUPER_ADMIN` user UUID has been selected:

```bash
node backend/dist/scripts/installPressurePack.js --commit --admin-user-id <SUPER_ADMIN_UUID>
```

The command must finish with:

```text
PRESSURE PACK STAGED SUCCESSFULLY — DRAFT ONLY
No resource, question or assessment was published. Academic review remains mandatory.
```

If the supplied user is not a `SUPER_ADMIN`, the installer stops. If a matching resource/question/assessment is already `SUBMITTED`, `ACADEMIC_REVIEW`, `APPROVED`, `PUBLISHED` or `ARCHIVED`, the installer also stops instead of overwriting it.

## 4. Read-only verification

The following SQL is verification-only. It does not change data.

### Resource

```sql
SELECT public_slug,
       title,
       title_hi,
       review_status,
       visibility,
       class_min,
       class_max,
       subject_label,
       topic_label,
       is_featured_public,
       published_at
FROM learning_resources
WHERE public_slug = 'class-8-science-pressure-v1';
```

Required result before academic review:

- `review_status = DRAFT`
- `published_at IS NULL`
- `class_min = 8`
- `class_max = 8`
- English and Hindi titles present
- subject/topic labels identify Science / Pressure

### Question bank

```sql
SELECT COUNT(*)::int AS question_count,
       COUNT(*) FILTER (WHERE prompt_hi IS NOT NULL AND btrim(prompt_hi) <> '')::int AS hindi_prompt_count,
       COUNT(*) FILTER (WHERE explanation_hi IS NOT NULL AND btrim(explanation_hi) <> '')::int AS hindi_explanation_count,
       COUNT(*) FILTER (WHERE review_status = 'DRAFT')::int AS draft_count,
       COUNT(*) FILTER (WHERE published_at IS NOT NULL)::int AS published_count
FROM learning_questions
WHERE public_code LIKE 'VS8S-PRES-%';
```

Required result:

```text
question_count          = 12
hindi_prompt_count      = 12
hindi_explanation_count = 12
draft_count             = 12
published_count         = 0
```

### Bilingual options

```sql
SELECT COUNT(*)::int AS option_count,
       COUNT(*) FILTER (WHERE option_text_hi IS NOT NULL AND btrim(option_text_hi) <> '')::int AS hindi_option_count
FROM learning_question_options lqo
JOIN learning_questions lq ON lq.id = lqo.question_id
WHERE lq.public_code LIKE 'VS8S-PRES-%';
```

For objective questions, every stored English option must have a Hindi counterpart; therefore `option_count` and `hindi_option_count` must match.

### Assessments

```sql
SELECT public_slug,
       title,
       title_hi,
       summary,
       summary_hi,
       review_status,
       visibility,
       published_at
FROM learning_assessments
WHERE public_slug IN (
  'class-8-science-pressure-practice-v1',
  'class-8-science-pressure-mastery-v1'
)
ORDER BY public_slug;
```

Both rows must be `DRAFT` with `published_at IS NULL` and bilingual title/summary fields populated.

### Assessment question counts

```sql
SELECT la.public_slug,
       COUNT(laq.question_id)::int AS question_count
FROM learning_assessments la
LEFT JOIN learning_assessment_questions laq ON laq.assessment_id = la.id
WHERE la.public_slug IN (
  'class-8-science-pressure-practice-v1',
  'class-8-science-pressure-mastery-v1'
)
GROUP BY la.id, la.public_slug
ORDER BY la.public_slug;
```

Expected:

- practice: 8 questions
- mastery: 7 questions

## 5. Human review gates before publication

Installation is not approval. The following remain mandatory:

1. Science SME accuracy review;
2. Hindi academic-language review;
3. independent question/answer verification;
4. practical safety review;
5. captions/transcript/accessibility review for produced media;
6. final editorial approval.

Only after those gates should Learning Studio status transitions be used to move content through review and publication.

## Definition of complete for this pilot

The Pressure pilot is technically staged only when:

- repo Content Pack CI passes;
- the application TypeScript/build/regression workflows pass;
- the production/native deployment succeeds through the approved deployment script;
- installer dry-run succeeds in the deployed release;
- explicit DRAFT staging succeeds;
- the read-only checks above match the expected values.

It is **publication-ready** only after the human academic/language/safety/editorial gates and required media assets are complete.
